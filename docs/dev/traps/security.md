# Traps — Security and privacy

Conventions (entry shape, `★` `⚠` `⇒`, `§N`, `:NNNN`): [TRAPS.md](../TRAPS.md). Newest first within an area; new traps go at the top of their area.

## Security and privacy

- **python.org has no security flag, so a Python runtime fails only on EOL** (`scripts/deps_audit.py` `rt_verdict`, Harness runtime card). nodejs.org `dist/index.json` marks security releases (`security: true`); python.org `/api/v2/downloads/release` does not. ⇒ Node: a missed same-line security release = `fail`; Python: patch behind = `warn`, `fail` only when the cycle is EOL (`PY_EOL`).
  - ⚠No release list (offline, fetch error, own line not listed) = `unknown`, never `ok`; the viewer never fetches — only the runner writes `arch/deps-last.json`.
  - ⚠«Newest» counts Node even majors only (odd ones never reach LTS); every CPython minor counts.

- **A trivy run that cannot reach its vuln DB or registry is `fail`, never clean** (`sidereus/sec_trivy.py` `fail_why`, called before `net_fail` in `arch_checks._judge`). DB download errors ⇒ «vuln DB download failed: set TRIVY_DB_REPOSITORY»; UNAUTHORIZED / denied / 401 / 403 ⇒ «docker login <registry> needed»; MANIFEST_UNKNOWN / not found ⇒ «image not found».
  - ⚠DB is checked first: a rate-limited DB pull says «denied» too and must not read as a login problem.
  - ⚠An id with any failed row (one image of several) is left out of the scan record's ran-ok tools, so its old findings are not resolved by absence.
  - ⚠Several rows share one id (`trivy-image` per image, `npm-audit` per folder): `build` puts the id's count on its first row only — per-image numbers are `fixable` / `waiting`.

- **A security-checks run must not end on stage 1's output** (`sidereus/arch_map.py` `_sec_final_at`, state `secRun`). Stage 1 writes `checks-security.json` and appends a `src: "scan"` record to `security-log.jsonl`; ending on either (or on the log mtime) dropped the progress line during the threat-model review. ⇒ the run ends on a `src` `review` / `mark` record newer than the run start (log tail, cached by mtime+size) or on its run record closing; `pl_reqs` «Done» uses the same time.
  - ⚠The review may log nothing (no threat model): the end then comes from the record or the 180 s gap, never from the scan.
- **A «Request fix» line stayed «Delivered» after the fix and re-scan** (`sidereus/pl_reqs.py` `_state`, `checks-fix` record). Plain fix records returned only sent/gone and the page read the receipt. ⇒ `checks-fix` is `done` once `arch_map.result_at("security-checks", repo)` is newer than the send; the line shows «Done» ahead of ack/receipt. ⚠Not for `eval-fix`: a security result does not close an evaluation fix.
- **A «Request fix» closed on any re-scan, before anyone checked the fix** (`sidereus/pl_reqs.py` `_fix_state`, `security-fix` record). ⇒ «Request fix» is a `security-fix` run request carrying the finding `keys`; `done` only once that run's review stage (`REVIEW_STAGE`, the last title) is `done`, then `closed: <now>` is stamped once (hooks/pl_flow.py reads it). The page counts j/k on `keys` against the newer scan's `top`.
  - ⚠No `result_at` / superseded shortcut for security-fix: a scan or a newer request is not a reviewed fix. ⚠A key absent from `top` reads fixed — past TOP_MAX (50) a finding pushed out by higher ones also does.
  - ⚠Keys are tab-joined (84l `archChkKey`): `_KEY_CTRL` allows TAB only. ⚠`_write` sheds the oldest records past READ_MAX — `_read` drops the whole file above it.
- **Hidden security rules persist across scans and lower the tab badge** (`web/js/84l-structure-arch-checks.js`, ui-pref `sidereus.ckhide`, per repo). Hiding is view-only, so a new scan that still finds a hidden error keeps it out of the count; with only hidden errors left the badge turns amber, not red. ⇒ the badge tooltip states how many rules are hidden and the window shows «N rules hidden · Show».
  - ⚠Never drop the hidden count from the tooltip, and never write hiding into `checks-security.json`, `security-log.jsonl` or the report — false positives stay CLI-only (`scripts/arch_checks.py --mark … false-positive`).
- ★**Security reports are pruned with a real `os.remove`** (2026-10-17, `sidereus/sec_report.py`). Reports are generated data the next run rebuilds; «delete never deletes» (AGENTS.md rule 7) covers tool config only. ⇒ prune keeps the newest `KEEP` (10) names matching `REPORT_RE`; other names and symlinks are never touched. `read_text` refuses bad names, symlinks, files over 256 KiB and paths whose realpath leaves the dir.
  - ⚠Never put tool message text, secret values or the AI-review `desc` in the report — rule id · `file:line` · severity (+ package) and runner-composed status words only.
- ★**«Security tools» must find a tool installed after the viewer started, without running it** (2026-10-17, `sidereus/sec_tools.py`). launchd's PATH is `/usr/bin:/bin:/usr/sbin:/sbin`, and `ident.bin_path` caches a miss forever. ⇒ `_which` = `shutil.which(name, path=ident.rich_env()["PATH"])`, no cache; version from `os.path.realpath` layout only (Cellar segment, npm package.json, dist-info).
  - ⚠Never `--version` the tool (rule 7) and never use `bin_path` here. ⚠Brew's `bin/npm` resolves to `npm/bin/npm-cli.js`, not a Cellar path — check both the link dir and the realpath dir.
- ★**Work log was readable by another OS user on a shared Mac** (2026-10-16). Loopback alone does not tell users apart. ⇒ `sidereus/peer.py`: on macOS the `/work` APIs need `lsof` to find the client end held by a process of the viewer's UID; non-root `lsof` cannot see other users' sockets, so «no same-UID client end found» also covers the other-user case.
  - ⚠Filter on the client end (`<cport>-><viewer port>`), not the viewer's accepted socket — that one is always the viewer's own UID.
  - ⚠Cache allows only (5 s per client port); never cache a refusal.
  - ⚠Missing `lsof` or a real miss ⇒ popup 403; a slow one is the next entry. Fail-closed is intended; do not fall back to allow.
- ★**Peer check timeout under load read as refusal** (2026-10-23). At load ~165, 10/13 `/api/session/work` got 403 (2.9–32.5 s); at 85–120, 20/20 OK. `lsof` overran 1.5 s and `except: return False` made it a refusal ⇒ empty popup.
  - ⇒ `peer_state()` = True/False/None: a timeout or start failure retries once at 5 s (`PEER_TIMEOUTS`), then None. Routes answer None with 503 + `Retry-After: 2` (`_peer_refused`); `workGetJSON` shows «Viewer is busy — retrying…» and backs off 2/4/8/16 s.
  - ⚠None never allows and is never cached; 403 is not retried by the backoff. Test `tests/test_work_peer.py` · `tests/test_work_busy_js.py`.
- ★**`/api/ui-prefs.js` served `window.__UIP=…` (10 of 49 keys hold local paths) as executable JS** (2026-10-16). The shared GET guard passes a missing `Sec-Fetch-Site` (curl/hooks/OTel), so a browser without Sec-Fetch-* let a cross-origin `<script src>` read it. ⇒ `_g_ui_prefs` returns 403 unless `Sec-Fetch-Site` is exactly `same-origin`; the page then sees `__UIP` undefined ⇒ defaults in memory, nothing posted (web/app-head.js). Test `test_get_requires_same_origin`. ⚠Never serve private data as executable script without a same-origin check.
- ★**The «Source» popup can open any file of CODE_DIR, and CODE_DIR is the mailbox data dir** (2026-09-29, `sidereus/structure_tree.py`). It holds `bus.jsonl` and other conversation data. ⇒ a file opens only if it is in the listing AND its realpath stays under the root; `*.jsonl` and anything under realpath(~/.claude) are refused; secret names lock, `PRIVATE KEY-----` refuses, other lines go through `redact()`. ⚠Never serve a path that skipped the listing check, and never drop the `*.jsonl` refusal.
- ★**Handler had no socket timeout — one stalled client pinned a thread forever (slowloris)** (2026-09-25 audit). ⇒ `Handler.timeout = 30` (chat_server.py). ⚠No route holds a connection open; a future long-poll/SSE route must set its own socket timeout instead of removing this.
- ★**`Sec-Fetch-Site: same-site` passed the API GET guard** (2026-09-25 audit — a page on another 127.0.0.1 port could hit `/api/wkuse?force=1`). ⇒ `do_GET` refuses `cross-site` and `same-site` under `/api/`; `same-origin`, `none` and no header (curl/hooks/OTel/MCP) pass. ⚠Do not re-allow `same-site`: every localhost port is same-site.
- ★**Data files were 0644 / dirs 0755** (2026-09-25 audit). ⇒ `_atomic_write` creates tmp as 0600, appends go through `bus._open_append` (0600 on create), `backup.sh` runs `umask 077`; existing jsonl/viewer.err/log/backups chmod 600, `backup/` 700. ⚠No global `os.umask` in the server — git/subprocess writes into user repos would inherit it.
- ★**Two unescaped values in HTML** (2026-09-25 audit): session `x.state` in a class attr (40b-sessions-list.js) and token-chart date labels (46-tokens-tab.js). ⇒ both wrapped in `esc()`. ⚠Server-sent strings always go through `esc()`, even ones that "can only be an enum".
- ★**«Tools» MCP file view showed a DSN password in clear** (2026-10-05 live settings audit, `postgresql://user:PASS@host` in `args`). `redact()` keys on secret words; a connection string has none, so its `_HINT` pre-check skipped it. ⇒ `_USERINFO` masks the userinfo password (user kept), `_HINT` matches `://`; `mask_mcp` also redacts `command`. Tests `test_url_userinfo`, `test_mcp_dsn_password_masked`. ⚠Use fake DSNs in tests — never paste a real one.
- ★**One-line labels reached /api/state and /api/v1/state unredacted** (2026-10-05 audit). Agent `description`, SendMessage `summary`, bg Bash `description`, workflow `label` and room `topic` are free text; `https://u:pw@host` or `token=…` in one went to the page and the public API as-is. ⇒ `redact()` at the source where each label is built (`bgtasks_parse._sub_label`/`_bg_on_launch`, `agents` tool `now`/`_wf_journal`/wf meta, `recent._agent_desc`, `redact_rooms` in `state`, `state_v1._rooms`; meta `description` reads in `history`, `failures_scan`, `agentcost`, `burn_scan`, `file_owner._who`). Tests `tests/test_label_redact.py`. ⚠Redact **before** the length cut — a cut `u:pw@` loses its `@` and escapes the mask. ⚠A new label source must redact too; consumers do not.
- ★**Work log showed secrets from raw tool results** (2026-09-25 audit, a `cat .env` put keys on screen). ⇒ `session_work`/`agent_work` return through `redact_work` (sidereus/redact.py) — masks results lines, arg/targ, says, prompt, edit bodies. ⚠Any new raw-text field in that payload must go through it too.
- ★**A session started in ~ or / made the whole home readable via `/api/structure/src`** (2026-09-25 audit). ⇒ `_struct_allowed_roots` subtracts `/` and the pwd home (`_struct_denied_roots`, sidereus/structure.py); repos under ~ still pass. ⚠Take home from `pwd`, not `$HOME` — an overridden `$HOME` must not block CODE_DIR.
- ★**Rule 1 leaks: session rows and /api/failures carried message text and tool input** (2026-09-25 review — drawer showed `reply`/`task`/Bash commands; failure samples sent raw tool output, wreckage steps sent `arg`). ⇒ Stripped at the payload builders: `_session_row` (no `task`/`reply`, `targ` = Agent description only, sidereus/sessions.py), `_agent_last`/bg labels (tool name or description only, agents.py · bgtasks_parse.py), `failures()` (`_pub_sig` = fixed label + tool name from the tool_use id map `_FAIL_TNAME`, no sample `text`), `_agent_trace` steps (no `arg`), `/api/retro` sigs (same `_pub_sig`), ask/abort transition cards (empty body, `task` read only to skip /exit·/clear, notes.py), demo rows/cards. Guarded by tests/test_metadata_only.py. ⚠Never widen these back with "just a short summary" — only the click-to-open work log may show text. Internal `sig`/`text` stay server-side (attention's benign filter, cards).
- ★**Repo-local git config could run code in a repo a session merely touched** (2026-09-25 security audit: `core.fsmonitor`, `diff.external`, textconv) ⇒ every spawn uses `gitinfo.git_argv()` (`-c core.fsmonitor=false -c core.hooksPath=/dev/null`, plus `--no-ext-diff --no-textconv` for diff/show/log); diff bodies use `_git_run_capped` (keeps DIFF_MAX+1 chars, only counts the rest for `cutBytes`, kills at `GIT_COUNT_MAX`). ⚠New git calls go through `_git_run`/`git_argv`. On git >= 2.40 (probed once at import) `--attr-source=<empty tree>` stops `.gitattributes` filter drivers (clean/process) — LFS/eol attributes are ignored for display; ⚠`.git/info/attributes` and git < 2.40 are still not covered. Test `tests/test_git_safe_opts.py` (FilterDriver: real temp repo, marker file + plain-git control).
- ★**Host header check** (2026-09-23 · DNS rebinding). First line of `do_GET`/`do_POST` is `_host_ok()` — anything but `127.0.0.1:PORT` · `localhost:PORT` is 403. No exempt paths.
  - ⚠OTel, `ext_hook.py` and the saver hook all send to `http://127.0.0.1:8799`. Changing a sender URL to a hostname other than these is blocked. The bind host is fixed to 127.0.0.1 in `main()`.
  - All lock/concurrency items from the 09-23 review are closed (rechecked 09-24): `saver_set` = `_saver_lock` · 7 races + mark-all-read = `df5d72c` · `4ed01b2` (unchanged after the split).
  - ⚠Left open (not a race): no cap on concurrent `git_commit` requests (≤4 git calls × 6 s per request). No shared state, and other git GETs are the same — a cap would go on all git GETs at once.
  - ★Added 09-24: `gitinfo._GIT_SEM` (3 concurrent git) — every git call goes through `_git_run` · `_git_slot`. Slot wait over 10 s = `TimeoutExpired` (existing "timeout" path) · branch warm-up skips the tick if it cannot get a slot within 0.2 s. ⚠New git calls use these two, never `subprocess` directly.
- ★**Hook attachments carry the hook's output and its full command** (2026-10-03, `sidereus/toolidx.py`): `hook_success` has `content`/`stdout`/`stderr`/`command`, `stop_hook_summary` has `hookAdditionalContext`. ⇒ only `type`/`hookName` + record `uuid` are read, plus `command` reduced at once to a 12-hex sha1 (`toolidx.hook_hash`, `hookc:<hookName>#<hash>` keys) so each hook gets its own count — `command` is the configured string verbatim (checked on user hooks). ★`hook_success` is written **only for runs that printed output** (3 days: agent-brief 602 · cc-status 13775 · hook.mjs 130 records; silent pl-mark/live-verify-gate/saver_limit 0, though they run on every call). ⇒ a hook with no record shows «?» (`quiet`, n None), never 0 and never the `hook:<Event>` total — that key mixes every group's records (a matcher-less group borrowed 82300 = the event total); one run that injects writes both `hook_success` and `hook_additional_context`, so they count under `hook:` and `hookctx:` separately. ⚠Never read the other attachment fields; summing the two types double-counts.
- **A hook with no record = runs unknown, never 0** (`sidereus/harness_verdict.py` `idle`): silent hooks write no `hook_success`, so «0 runs» cannot mean unused (pl-mark / live-verify-gate run on every call and have 0 records). ⇒ `idle` only when a tool-event matcher fits none of the tool names used in the window (`harness._nomatch`, toolidx `tool:<Name>` keys); never while the index is still scanning. ⚠Never flag a hook as unused from `n`, nor from «other hooks on the event ran».
- **«Pass stability» `reverted` = exact one-commit tree rollback only** (`sidereus/harness_trail.py` `_git_state`): a later commit (≤50 after the PASS head) whose tree equals `<head>^`'s. ⇒ a partial revert or a revert squashed with other changes reads as «Stable» — and the Harness report's `reverted` count (`report()`) counts it as `held`. `broke` counts the same mode with overlapping rc≠0 steps only (a `--fast` FAIL never breaks a `--full` PASS). A dirty PASS is «Unverified» with no git call. ⚠Git here is hash-only (`%H%x09%T`, `--count`, `--is-ancestor`) — never `%s`, `--stat` or a diff (rule 1). Exception: the flow «Edit» node (`sidereus/harness_flow.py` `_diff`) uses `diff --numstat` — paths and +/- counts only, no patch text; that is metadata, keep it.
- **Harness guard `deny` was always None** (`sidereus/harness_flow.py` `guards()`, the «before edit» checkpoint; was the «Flow» guard node): `hooks/pl_flow.py` denials were returned to the model and written nowhere.
  - ⇒ pl_flow.py now counts them on the run (`deny`, `dl` = last 20 {t, stage title, code jump|agent|model|tag|stage}); the node shows «blocked n». Runs written before the field still show «not recorded». ⚠Never render a missing deny count as 0 — that claims «no violations». ⚠`dl` never holds tool input: an unknown stage title is stored as "".
  - ⚠A deny with no open run writes nothing (a refused first dispatch must not create an empty run); a jump deny still saves the run as before.
  - ⚠Run history depth = what `plmark/<sid>.runs.json` still holds: one entry per pipeline name per session (a new run of the same name overwrites it), files read newest 40, kept 7 d here (`pl_runs` drops > 6 h for live lighting).
- ★**Harness «?» tooltips never showed** (2026-10-07, measured: the `.hntip` node was replaced after 2 s). Harness HTML changes every poll (relative times), so `plRender` rebuilt it by `innerHTML` and the native `title` tooltip died before its ~1 s delay. ⇒ the poll repaint is skipped while the pointer is on a `.hnw [title]` (`web/js/48-pipeline.js`). ⚠Do not move the help text to a custom hover card unless the guard is kept — any rebuilt node loses hover.
- **An MCP failure stays «last» unless a connect clears it** (`sidereus/toolidx.py` `mcp_status`): a connected but unused server has no call newer than an old failure. ⇒ `deferred_tools_delta` `addedNames`/`readdedNames` (`mcp__<srv>__*`) count as success evidence (per-file `conn`, cache v2). ★10-05: chrome-devtools/context7/sequential-thinking failed 6–8 days ago, connected 2.5 h ago.
- ★**MCP failures live in `deferred_tools_delta` attachments, not a dedicated record** (2026-10-03, `sidereus/toolidx.py` `_fails_of`): `attachment.failedMcpServers` = `[{name, errorCode, error}]` (16 of 1334 had `name` only), repeated as a snapshot in every delta (1227 records / 5 servers); `pendingMcpServers` = plain strings. `error` is free text. ⇒ read `name` + `errorCode` (`[A-Z_]{1,24}`) only; names map to the tool prefix via `[^A-Za-z0-9_-]`→`_`. ⚠Undocumented shape — if Claude Code moves the field, status silently falls back to «not recorded»; never read `error`.
- ★**v1 omits `targ`/`blocked`** (2026-10-05, `sidereus/state_v1.py`): both are derived from tool input (Agent description, blocked command).
  - ⇒ the public schema carries ids, paths, model, state, timestamps and counts only.
  - ⚠Never add a v1 field that can carry message or tool content — external consumers are outside the work-log exception.
  - Adding an optional field is allowed in v1; removing or renaming a field, or changing its meaning = `v2`.
- **Workflow phase list comes from the saved script, which holds prompts** (2026-10-06, `sidereus/wf_meta.py`): `<sess>/workflows/scripts/<name>-wf_<id>.js` is the whole script.
  - ⇒ only `meta.phases[].title` string literals (<=12, <=40 chars, redacted) from the first 16 KB; any `${`, non-literal title or parse error = [] and the journal phases stand in.
  - ⚠Never read `wf_<id>.json` or the script body/args/result for anything else — they carry prompts and agent output.
- **CSP: adding an external source** (`sidereus/routes_get.py` `PAGE_CSP`, sent by `_page_reply` for `/`, `/diff`, `/work`, `/brdiff`).
  - Same-origin only: a CDN script/font, a fetch to another host or port (OTel collector, update check), or an `<iframe>` is silently blocked; the console shows the CSP violation.
  - ⇒ widen the one directive that needs it in `PAGE_CSP` with a `⚠` comment on why. `img-src data:` is the favicon swap (`15-alarms.js`).
  - ⚠Never drop `frame-ancestors 'none'` / `X-Frame-Options: DENY` (clickjacking on Send/Apply buttons) or `connect-src 'self'`.
- **Draft strip «Session received» reads ack `who` only** (`48e plDraftSteps`). ⚠Never read or render ack `note` (reply text, rule 1); `hooked`/`delivered` do not mean the session read it. Test `tests/test_pipeline_draft.py` checks a sentinel note never reaches the HTML.
- **Image endpoint `GET /api/structure/img`** (`sidereus/structure_tree.py` `structure_img`, inline Markdown images): same guards as `/api/structure/file` (allow-list root · listing · realpath under root · ~/.claude · secret names).
  - ⚠The extension is checked on the realpath too: `a.png` symlinked to a text or secret file would otherwise be served as an image.
  - ⚠svg is active content: only ever shown via `<img>` (no script there), and the response carries `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox` + nosniff for a direct open. Never embed it as `<object>`/`<iframe>`/inline markup.
  - ⚠5 MB cap (`IMG_MAX_BYTES`) checked by `getsize` before reading, then rechecked on `cap+1` bytes read. Mime is fixed per extension (`IMG_TYPES`), never sniffed.
- **Severity levels replaced error/warning** (`sidereus/arch_checks_parse.py` `SEVS`/`level`, checks file v2): stored v1 files and old log lines are read converted (error → high, warning → medium).
  - ⚠A v1 result never shows critical or low — the tool's finer level was not kept; only a rescan gives real levels.
  - ⚠The gate (`checks_errors`) accepts v2 only; the page loader accepts v1 and v2. Never write error/warning into a v2 file.
    `--verify --last` on a v1 file of the current HEAD fails until the next scan; `--log-review` rows with error/warning are read as high/medium too.
- **Security log status is computed on read, never rewritten** (`sidereus/sec_checks.py` `log_view`, `arch/<key>/security-log.jsonl`).
  - Identity = (src, key, file), not line. A scan finding resolves only when a later scan in which its own tool ran ok omits it; it reopens if it comes back.
  - ⚠AI review findings are never resolved by absence: model review is not deterministic, so a missing finding is not evidence of a fix. Only a `--mark` record resolves them (last mark wins).
  - ⚠Scan and review never resolve each other; a run where no tool ran ok is not logged (it would resolve everything).
  - ⚠Records hold sev · file:line · key · one-line desc only — never Match / Secret / message text or source lines.
- **gitleaks `dir` scans gitignored files** (`scripts/arch_checks.py` `run`, `sidereus/sec_checks.py` `drop_ignored`): ★1017 generic-api-key errors from local `.omc/` state filled the item cap (300) and the log cap (200), hiding real findings.
  - ⇒ after the scan, drop items under `git ls-files -z -o -i --exclude-standard --directory`; a git failure keeps every item.
  - ⚠Gitignored files (often `.env`) are skipped on purpose — they are not committed; never hard-code dot-dirs (would hide committed `.github` / `.env`).
- **Work log cut before redact** (`sidereus/steps.py` `_cut`, all caps in `_scan_blocks` / `_work_scan`): ★a fake DSN straddling the 4000 say cap showed `postgresql://u:FakePw123` — `_USERINFO` needs `@`, `_JSONKV` the closing quote.
  - ⇒ `_cut` redacts `s[:n + 2048]` then cuts; `redact_work` stays as the second pass; `cut` flags compare raw lengths.
  - ⚠Never cut raw text before redacting it.
- **Issues window: empty list and stale CSS** (`web/js/84l-structure-arch-checks.js` `archChkWinHtml` · `archChkWinCss`): 0 findings still emitted `<ol>` + grip, so the saved `sidereus.ckwh` (423 px) painted a tall empty box; the window's `<style>` was copied only when written, so a repaint after a viewer reload kept old CSS (right side clipped).
  - ⇒ empty top = one `.archckst` status line, no grip (split off); every paint resyncs the window `<style>` when the opener CSS differs; `#ckroot` has `overflow-x:auto`.
  - ⚠Never emit an empty findings `<ol>` — `archChkSplitEls` keys the split on both lists existing.
- **«Request fix» line closes on evidence only** (`sidereus/pl_reqs.py` `_fix_commit` · `web/js/84l-structure-arch-checks.js` `archChkFixRecHtml`): an ack note («fixed») is the session's word, not proof.
  - ⇒ «fix commit seen <hash>» = oldest `git log --since` commit with ct > request `at`; «re-scan done — n issues left» = newer security-checks result, n = window title count.
  - ⚠Only a `[0-9a-f]{7,12}` hash reaches the page (fullmatch on server and page) — never commit subject/body. Hit cached for good, miss 30 s, 64 entries.
